## 一、测试目标与范围

### 1.1 测试目标

1. 验证各业务模块功能与设计方案一致。
2. 验证权限控制、状态流转、冲突校验等关键规则正确。
3. 验证接口契约（入参/出参/状态码）稳定。
4. 发现并记录缺陷，评估系统是否达到可交付标准。

### 1.2 测试范围

| 纳入 | 说明 |
| --- | --- |
| 功能测试 | auth / assets / borrow / inventory / inspection / teaching / report |
| 接口测试 | 全部 REST 接口，含鉴权与异常分支 |
| 业务规则测试 | 资产状态流转、预留冲突、逾期判定、盘点差异 |
| 非功能测试 | 性能、安全、兼容、易用性 |

| 不纳入 | 说明 |
| --- | --- |
| 家长端 | 本期未开发 |
| IoT 硬件 | 本期未开发 |
| 大规模压力 | 仅做小规模并发验证 |

- 首次启动自动写入种子数据：`admin` / `logistics` / `teacher`（密码均为 `admin123`）。

## 三、测试策略与方法

| 层次 | 方法 | 说明 |

| 接口层 | 接口测试 | 使用 Swagger/Postman 覆盖正常与异常分支 |

## 五、接口测试要点

## 七、缺陷分级与处理流程

### 7.1 缺陷分级

| 等级 | 名称 | 定义 | 示例 |
| --- | --- | --- | --- |
| S1 | 致命 | 系统不可用、数据丢失、越权/安全漏洞 | 服务崩溃、SQL 注入可提权 |
| S2 | 严重 | 核心功能不可用或结果错误 | 借出后状态不同步、盘点差异计算错误 |
| S3 | 一般 | 非核心功能异常或有可绕过的错误 | 筛选条件部分失效、提示文案错误 |
| S4 | 轻微 | 界面/文案/体验问题 | 对齐错位、错别字 |

### 7.2 处理流程

1. 发现 → 记录（用例编号、步骤、期望、实际、截图/日志、等级）。
2. 指派 → 修复 → 回归验证 → 关闭。
3. S1/S2 缺陷须全部关闭方可发布；S3/S4 可评估后延期。

## 八、验收标准

发布前须满足：

1. 所有 P0 用例通过率 100%。
2. P1 用例通过率 ≥ 95%，且无未关闭的 S1/S2 缺陷。
3. 接口契约与设计方案一致，Swagger 文档可用。
4. 核心业务闭环（借还、盘点、巡检、预留）端到端跑通。
5. 安全测试项 ST-001 ~ ST-004 全部通过。
6. 分权分域验证通过：`all / org / self` 三种数据范围隔离正确，跨域访问被拒。
7. 加密验证通过：密码哈希、敏感字段加密落库、脱敏展示均符合设计。

## 十、风险与注意事项

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| SQLite 并发写 | 高并发写入可能锁表 | 控制并发量，必要时迁移到 PostgreSQL |
| 种子数据污染 | 用例间数据相互影响 | 用例前重置数据库或使用独立测试库 |
| 日期相关用例 | 逾期/到期依赖当前日期 | 使用相对日期构造数据（今天±N 天） |
| 权限用例覆盖不足 | 角色多、组合多 | 建立权限矩阵逐项验证 |
