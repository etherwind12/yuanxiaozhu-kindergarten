## 一、项目概述

### 1.1 背景与痛点

幼儿园的资产远不止玩具：除玩教具外，还有教学设备、电器家具、体育器材、图书绘本、办公用品、被褥园服、消防安防设施等各类资产，种类多、数量杂。日常存在以下问题：

- **台账乱**：Excel 手工登记，借出/归还靠口头或纸笔，账实不符。
- **监管难**：玩具、器械、消防设施等的**消毒**与**安全检查**到期无人提醒，存在安全隐患。
- **教学脱节**：教师备课时不知道园里有哪些可用教具、是否被占用，资产"只管不用"。
- **盘点累**：月末盘点全靠人工清点，效率低、易出错。

### 1.2 项目目标

建设一套轻量、可私有化部署的园务资产管理系统，实现：

1. 全类资产台账数字化：**玩具只是其中一类**，覆盖设备、家具、图书、消防等全部资产（二维码一物一码，扫码借还）。
2. 资产全生命周期管理（在库 / 借出 / 维修 / 报废 / 遗失）。
3. 消毒与安全检查的**到期预警 + 巡检闭环**。
4. 资产与教学打通：教师按主题/领域检索并**预留**教具。
5. 盘点任务化、扫码化，自动生成差异。
6. **分权分域**（功能权限 + 数据域隔离）与**数据加密**，满足园所数据安全与合规要求。

### 1.3 项目范围

- **包含**：全类资产台账与分类体系、借还、盘点、巡检（消毒/安全）、教学预留、统计报表、**分权分域**、**数据加密**。
- **不包含**：财务核算、人事考勤、家长端、IoT 硬件对接（均作为后续扩展）。

## 二、总体架构

采用**前后端分离**，两端各自内部再按**模块化分层**组织，保持高内聚、低耦合。

```
┌────────────────────────────┐      HTTP / JSON      ┌────────────────────────────┐
│         前端 npm             │  ───────────────────▶ │         后端 Python          │
│  Vite + React               │  ◀─────────────────── │  FastAPI                    │
│  路由层 / 页面模块 / 组件 / 接口层  │        JWT 鉴权        │  接口层 / 业务层 / 数据层 / 公共层 │
└────────────────────────────┘                       └──────────────┬─────────────┘
                                                                     │ SQLAlchemy ORM
                                                          ┌──────────▼───────────┐
                                                          │       SQLite         │
                                                          └──────────────────────┘
```

### 2.1 后端分层（Python / FastAPI）

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 接口层 | `app/modules/*/router.py` | 定义 HTTP 路由、参数校验、鉴权依赖 |
| 业务层 | `app/modules/*/service.py` | 业务规则、事务、状态流转、数据域过滤 |
| 数据层 | `app/modules/*/models.py` | SQLAlchemy ORM 模型 |
| 契约层 | `app/modules/*/schemas.py` | Pydantic 请求/响应模型 |
| 公共层 | `app/core`、`app/common` | 配置、数据库、安全、加密、通用依赖 |
| 初始化 | `app/db/init_db.py` | 建表、种子数据 |

### 2.2 前端分层（npm / React）

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 路由层 | `src/router` | 页面路由、登录守卫、权限守卫 |
| 页面模块层 | `src/modules/*` | 按业务模块划分的页面 |
| 组件层 | `src/components` | 通用 UI 组件 |
| 接口层 | `src/api` | 统一 axios 封装与各模块 API |

### 5.2 关键枚举

- **资产大类**：玩具、教具、图书绘本、教学设备、电器家具、体育器材、办公用品、生活用品（被褥/园服）、消防安防、其他。**玩具仅为其中一类**。
- **数据域类型**：园区 / 楼栋 / 班级（树形组织，`org_units.type`）。
- **数据范围**：`all` 全园 / `org` 本组织域及下级 / `self` 仅本人。
- **资产状态**：`in_stock` 在库 / `borrowed` 借出 / `repairing` 维修中 / `scrapped` 已报废 / `lost` 遗失。
- **借还状态**：`borrowing` 借用中 / `returned` 已归还（逾期由 `due_at` 实时判定）。
- **巡检类型**：`disinfect` 消毒 / `safety` 安全检查；状态 `pending` 待处理 / `done` 已完成。
- **盘点结果**：`pending` 未盘 / `matched` 相符 / `diff` 差异。
- **预留状态**：`pending` 待审批 / `approved` 已通过 / `rejected` 已驳回 / `finished` 已结束。
- **角色**：`admin` 园长 / `logistics` 后勤 / `teacher` 教师 / `caregiver` 保育员。
- **五大领域**：健康、语言、社会、科学、艺术。

### 5.3 实体关系

- 组织域为树形：园区 → 楼栋 → 班级（`org_units` 自关联）。
- 一个组织域含多个用户、多个资产（1:N）。
- 一个分类含多个资产（1:N）；分类支持父子层级。
- 一个资产可挂多个标签，一个标签可挂多个资产（N:N，经 `asset_tags`）。
- 一个资产有多条借还记录（1:N）。
- 一个盘点任务含多条盘点明细（1:N）。
- 一个巡检任务可对应 0 或 1 个资产，产生多条巡检记录（1:N）。
- 一个资产可有多条预留记录（按日期区分）。

## 七、分权分域与数据加密

系统采用「**分权**（功能权限）+ **分域**（数据权限）+ **加密**（数据安全）」三位一体的安全模型。

### 7.1 分权 —— RBAC 功能权限

- 模型：**用户 → 角色 → 权限点**，角色可扩展（当前内置 4 个）。
- 权限点粒度：菜单可见、操作按钮（增/改/删/审批/导出）两级。
- 后端通过 `require_roles(...)` / 权限点依赖做接口级校验；前端按权限渲染菜单与按钮。

| 角色 | 资产查看 | 资产增改删 | 借还 | 盘点 | 巡检 | 预留申请 | 预留审批 | 用户/权限管理 |
| --- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 园长 admin | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ |
| 后勤 logistics | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ | ✘ |
| 教师 teacher | ✔ | ✘ | ✔ | ✘ | ✘ | ✔ | ✘ | ✘ |
| 保育员 caregiver | ✔ | ✘ | ✔ | ✔ | ✔ | ✘ | ✘ | ✘ |

### 7.2 分域 —— 数据域权限

- 组织为**树形数据域**：园区 → 楼栋 → 班级（`org_units`）。
- 关键业务数据（资产、借还、盘点、巡检、预留）均带 `org_unit_id` 归属域。
- 用户绑定归属域与**数据范围** `data_scope`：

| 数据范围 | 可见数据 | 典型角色 |
| --- | --- | --- |
| `all` 全园 | 全园所有域数据 | 园长 / 集团管理员 |
| `org` 本域及下级 | 本人所属组织域及其下级域数据 | 后勤、年级组长 |
| `self` 仅本人 | 仅本人创建 / 负责的数据 | 教师、保育员 |

- 机制：所有列表与详情查询在 service 层**强制注入域过滤条件**；跨域读取或写入直接拒绝（403）。
- 效果：既"分权"（能做什么），又"分域"（能看 / 改哪些范围的数据）。

### 7.3 字段权限与脱敏

- 敏感字段（手机号、家长联系方式等）默认**脱敏展示**（如 `138****1234`），仅园长与数据本人可见全量。

### 7.4 数据加密

| 层面 | 措施 |
| --- | --- |
| 传输 | 全站 HTTPS / TLS，杜绝明文传输 |
| 密码 | PBKDF2 加盐哈希存储（不可逆），登录校验使用恒定时间比较 |
| 敏感字段 | 手机号、身份证、家长联系方式等 **AES 对称加密**后落库，密钥由环境变量 / 密钥服务提供，**禁止硬编码** |
| 数据库文件 | 可选 **SQLCipher 整库加密**；数据库与备份加密存放 |
| 令牌 | JWT 短有效期 + 刷新；登出 / 改密后旧令牌失效 |
| 审计 | 关键操作留痕（操作人、时间、对象、动作、结果），日志只读、不可篡改 |
| 备份 | 备份文件加密，恢复需授权 |

> 数据安全原则：最小权限、默认拒绝、敏感数据加密与脱敏、操作可追溯。

## 八、关键业务流程

> 以下流程均在当前用户的**数据域范围**内执行，跨域数据不可见、不可操作。

### 8.1 借出与归还

1. 教师扫码/选择资产 → 系统校验资产状态为「在库」→ 生成借还记录（借用中）→ 资产置为「借出」。
2. 归还时定位记录 → 记录置为「已归还」并写 `return_at` → 资产回到「在库」。
3. 超过 `due_at` 未归还的记录，在列表中实时标记「逾期」。

### 8.2 盘点

1. 发起盘点 → 系统为**当前数据域内**的资产生成明细（记录账面数量）。
2. 现场扫码/登记实际数量 → 系统自动判定「相符」或「差异」。
3. 结束盘点 → 输出差异清单。

### 8.3 巡检（消毒 / 安全检查）

1. 手动新建巡检任务，或按资产的 `disinfect_due` / `safety_check_due` **批量生成**待处理任务。
2. 责任人执行后登记结果（合格/不合格）与备注 → 任务置为「已完成」。
3. 逾期的待处理任务在总览中预警。

### 8.4 教学预留

1. 教师按领域/使用日期检索**可预留教具**（在库且当日无有效预留）。
2. 发起预留（关联课程主题与使用日期），系统做**当日冲突校验**。
3. 后勤/园长审批通过或驳回；使用完成后结束预留。

| 性能 | 单园所数据量下，列表接口响应 < 500ms；支持 50 人并发 |
| 可用性 | 核心流程 3 步内完成；移动端可扫码操作 |
| 安全 | 分权分域（RBAC + 数据域强制过滤）；密码 PBKDF2 加盐哈希；敏感字段 AES 加密与脱敏；HTTPS 传输；JWT 鉴权；操作审计；SQL 注入由 ORM 参数化规避 |
| 数据 | SQLite 单文件，便于备份与私有化部署；支持 SQLCipher 整库加密；备份加密 |
| 兼容 | 现代浏览器（Chrome/Edge）；后端 Python ≥ 3.10；Node ≥ 18 |
| 可维护 | 模块化分层，模块间通过 service 调用，禁止跨模块直接操作他方表 |

## 十、部署与运行

### 10.1 后端

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
# 接口文档：http://127.0.0.1:8000/docs
```

首次启动自动建表并写入种子数据（含组织域、分类、标签与示例资产），默认账号：`admin / admin123`（园长）、`logistics / admin123`（后勤）、`teacher / admin123`（教师）。

### 10.2 前端

```bash
cd frontend
npm install
npm run dev                     # 默认 http://127.0.0.1:5173
```

前端通过环境变量 `VITE_API_BASE`（默认 `http://127.0.0.1:8000/api`）访问后端。
